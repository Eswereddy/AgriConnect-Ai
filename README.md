government bodies, suppliers, logistics providers, financial institutions,

Gemini-powered intelligence behind diagnosis, forecasting, pricing, and
advisory features throughout.

representing any third-party app-building platform — everything in this
repository is a real Node.js/Express backend and React frontend you run,

## What this is

AgriConnect AI is a single application that serves **18 different
role-based dashboards** from one codebase — Farmer, Buyer, Government
Officer, Supplier, Agriculture Expert, Logistics Provider, Warehouse
Operator, Insurance Agent, Bank Officer, Researcher, Extension Officer,
Admin, plus dedicated modules for Precision Agronomy & Fintech, AI & IoT
integration, Blockchain & Carbon Credits, Mobile Apps, a Startup Pitch Hub,
and a Gemini AI/Maps/Firebase showcase suite.

Every role's dashboard is backed by real functionality: **30 API endpoints**
on the Express server, most of them calling Google's Gemini API for tasks
like crop disease diagnosis, yield forecasting, soil analysis, price
prediction, and multilingual chat — each with a graceful fallback path so
the app stays usable even if the API key is missing or a quota limit is
hit mid-demo.

On top of the original application, this repository also includes a
production-hardening layer: real authentication, a persistent database,
error monitoring, and rate limiting. See
[Authentication, database & monitoring](#authentication-database--monitoring)
below, and the full writeup in
[`AGRICONNECT_HARDENING.md`](./AGRICONNECT_HARDENING.md).

## Feature overview

| Area | What's there |
|---|---|
| Farmer tools | Crop diagnostics from photos, soil analysis, crop planning, yield forecasting, farm health reports, weather-adaptive advisory, smart alerts |
| Marketplace | Buyer/supplier price prediction, demand forecasting, bid suggestions, a peer-to-peer resource exchange with live trade negotiation over WebSockets |
| Logistics & warehousing | Route optimization, warehouse operations, a full supply-chain traceability module (batch tracing, smart contracts, tokenization, ZKP/IPFS-based provenance) |
| Government & finance | Subsidy scheme eligibility checks, disaster prediction, microloan and insurance workflows |
| AI Studio suite | Gemini-grounded chat, image generation & editing, audio transcription, Google Maps grounding, search grounding, and real Veo video generation with live status polling |
| Multilingual | Nine supported languages (English, Hindi, Telugu, Tamil, Kannada, Marathi, Gujarati, Bengali, Punjabi, Malayalam) with on-demand AI translation of generated content, not just static UI strings |
| Offline support | A service worker (`public/sw.js`) queues actions in IndexedDB while offline and syncs them back once connectivity returns |
| Accounts & security | Real registration/login (bcrypt + JWT), rate-limited auth, every API route gated behind a session, an admin promotion workflow |
| Reliability | Persistent SQLite storage for accounts and logs, structured request/error logging, optional Sentry integration, a one-command end-to-end verification script |

## Tech stack

**Frontend**
- React 19 + TypeScript, built with Vite 6
- Tailwind CSS 4
- `recharts` for charts, `d3` and `three` for richer visualizations, `@vis.gl/react-google-maps` for map views
- `lucide-react` for icons, `motion` for animation

**Backend**
- Node.js + Express 4, written in TypeScript, run with `tsx` in development and bundled with `esbuild` for production
- `@google/genai` — the official Gemini SDK, used directly (no separate backend-as-a-service layer)
- `ws` for the WebSocket-based live trade negotiation feature
- `better-sqlite3` for persistent storage, `bcryptjs` + `jsonwebtoken` for authentication, `express-rate-limit` for abuse protection
- Optional `@sentry/node` / `@sentry/react` for error monitoring

## Getting started

**Prerequisites:** Node.js 18 or later, and a
[Gemini API key](https://ai.google.dev/) if you want real AI responses
rather than the built-in fallback simulator.

```bash
# 1. Install dependencies
npm install

# 2. Configure environment variables
cp .env.example .env
# then edit .env — at minimum, set GEMINI_API_KEY and JWT_SECRET

# 3. Run the dev server (Express + Vite middleware, one process, one port)
npm run dev
```

The app is now running at `http://localhost:3000`. The SQLite database file
and `./logs` directory are created automatically on first run.

Register an account in the UI, then promote yourself to Admin if you want
access to the admin-only endpoints (`/api/auth/users`, `/api/auth/errors`):

```bash
npm run promote-admin -- your@email.com
```

**Production build:**

```bash
npm run build   # vite build (frontend) + esbuild bundle (backend) into ./dist
npm start        # runs the built server from ./dist/server.cjs
```

## Environment variables

All of these are documented with inline comments in
[`.env.example`](./.env.example) — copy it to `.env` and fill in what you
need.

| Variable | Required | Purpose |
|---|---|---|
| `GEMINI_API_KEY` | Yes, for real AI | Your Gemini API key. Without it, endpoints fall back to a built-in simulator so the app stays demoable. |
| `JWT_SECRET` | Yes, for real deployments | Signs login sessions. Without it, every server restart logs everyone out. |
| `GOOGLE_MAPS_PLATFORM_KEY` | For map features | Powers the interactive map views and GPS picker. |
| `DATABASE_PATH` | No | Where the SQLite file lives. Defaults to `./data/agriconnect.db`. |
| `DATA_DIR` / `LOG_DIR` | No | Override where the database directory / log files are created. |
| `SENTRY_DSN` / `VITE_SENTRY_DSN` | No | Enables Sentry error monitoring (backend / frontend) if set and the optional Sentry packages are installed. Otherwise errors log to SQLite + `./logs`. |
| `DEMO_MODE` / `VITE_DEMO_MODE` | No | Set both to `true` to disable login entirely — useful for a short pitch demo, not for real usage. |
| `APP_URL` | No | Self-referential URL, used for links back to the app if you need it. |

All 30 original application endpoints live in `server.ts`. They're grouped

**Farmer / crop intelligence**

`POST /api/analyze-soil` · `POST /api/smart-alerts` · `POST /api/yield-forecast` ·
`POST /api/farm-health-report` · `POST /api/agricultural-forecast`

**Marketplace**
`POST /api/quality-grading` · `POST /api/buyer/price-prediction` ·
`POST /api/buyer/logistics-optimize` · `POST /api/supplier/demand-prediction` ·
`POST /api/supplier/pricing-optimization` · `POST /api/supplier/product-generator` ·
`POST /api/suggest-bid` · `GET`/`POST /api/resource-exchange/listings`

**Government & risk**
`POST /api/scheme-eligibility` · `POST /api/disaster-predictor` ·
`POST /api/analyze-location`

**Gemini AI Studio suite**
`POST /api/gemini/chat` · `POST /api/gemini/generate-image` ·
`POST /api/gemini/transcribe-audio` · `POST /api/gemini/generate-video` +
`POST /api/gemini/video-status` (poll until `done: true`) ·
`POST /api/gemini/maps-grounding` · `POST /api/gemini/search-grounding`

**General-purpose**
`POST /api/chat` (role-aware multilingual assistant) · `POST /api/translate` ·

`POST /api/auth/register` · `POST /api/auth/login` · `POST /api/auth/logout` ·
`GET /api/auth/me` · `GET /api/auth/users` (Admin) · `GET /api/auth/errors` (Admin)

**Real-time**
A WebSocket server (`ws`) handles live trade negotiation chat for the
resource exchange feature — separate from the HTTP API above.

## Authentication, database & monitoring

The original application shipped without any real backend authentication —
switching roles was just a client-side state change. This repository adds:

- **Real accounts** — bcrypt-hashed passwords, JWT sessions in an httpOnly
  cookie, a proper login/register screen.
- **A login gate on every endpoint** — one middleware in `server.ts`
  requires a valid session for all 30 endpoints above, with zero changes to
  any of those endpoints' own code.
- **A persistent SQLite database** (`server/db.ts`) for accounts, a login
  audit trail, and an error log — survives restarts.
- **Error monitoring** — every request is logged; unhandled errors are
  captured to the database and `./logs/*.log`, with optional Sentry
  integration if you want it.
- **Rate limiting** on login/register to slow down credential stuffing.

Admin can't be self-assigned during registration — it's granted with
`npm run promote-admin`, run directly against the server's own filesystem,
not over HTTP.

Full details, including exactly which files changed and why, what's
deliberately *not* covered yet (per-role endpoint restrictions, the
in-memory demo caches, WebSocket auth), and a deployment note about
`better-sqlite3`'s native binding, are in
**[`AGRICONNECT_HARDENING.md`](./AGRICONNECT_HARDENING.md)**.

## Verifying it actually works

Reading the code (or having it reviewed) can confirm the logic is sound —
it can't confirm your API key is valid or that a specific endpoint isn't
quietly falling back. `verify-setup.mjs` actually calls the running app:

```bash
npm run dev        # terminal 1
npm run verify      # terminal 2
```

It registers a real test account, confirms unauthenticated requests get
blocked with a 401, then calls all 30 endpoints (plus the video generation
+ status-polling flow) with valid payloads and prints PASS/FAIL for each.

A PASS means the endpoint responded successfully — it can't distinguish a
real Gemini response from the built-in fallback simulator from the outside,
since both return the same JSON shape by design. Watch the `npm run dev`
terminal while it runs: a line reading
`[Precision Engine Mode] Live Gemini temporarily bypassed: ...` means that
specific call fell back (usually a missing/placeholder API key, or a quota
limit). No such line = everything really hit Gemini.

## Demo mode

For a pitch or investor walkthrough where signup friction isn't worth it,
set **both** of these and rebuild the frontend:

```
DEMO_MODE=true
VITE_DEMO_MODE=true
```

This disables the login screen and opens every endpoint to anonymous
requests. Leave both unset for real usage. `VITE_DEMO_MODE` is baked in at
build time, so toggling it requires `npm run build`, not just a restart.

## Deployment

This is a standard Node.js application — deploy it anywhere that can run
`npm install && npm run build && npm start` with a persistent disk for the
SQLite database file (or point `DATABASE_PATH` at a mounted volume).

The one thing worth knowing: `better-sqlite3` has a native binding compiled
for a specific OS/CPU. As long as `npm install` runs on the machine that
will actually run the server — the normal flow on most hosting
platforms — this is handled automatically.

## Known limitations & roadmap

- The 30 API endpoints are gated by login, not by role — any authenticated
  user can currently call any endpoint. Mapping each endpoint to the roles
  that should legitimately use it is a natural next step.
- In-memory demo caches (`aiCache`, `tradeSessions`, `videoOperations` in
  `server.ts`) still reset on server restart by design.
- The WebSocket trade-negotiation server isn't yet gated by the auth layer.
- The production frontend bundle is a single ~7.8MB chunk — code-splitting
  each role's dashboard with `React.lazy()` would meaningfully cut initial
  load time.
